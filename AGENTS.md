# AGENTS.md

Campus Forge: a campus-wide collectible MTG game. The backend owns the game; the headless Forge fork is only the battle rules engine; the PWA is the client. Architecture bible: `THEPLAN.md`. Per-phase plans: `STEPS/`.

## Layout
- `backend/` — Spring Boot 3.3 REST + WebSocket service on port **17172**. Code in `com.campusforge.backend.*` (accounts, collection, deck, battle, qr, trade, events, admin, analytics).
- `web-client/` — Vite + React 18 + TS PWA on port **17170**. `src/api/*` is the only layer that talks to the backend.
- `admin-console/` — standalone Vite + React 18 + TS admin app on port **17173** (proxy `/api` → 17172). Tabs: Events CRUD · Spawns · Players (search/ban/role) · Audit. Auth token in `localStorage` under `ac_token`.
- `forge-engine/` — full Forge fork (its own separate git repo; the root repo has zero commits). `forge-headless` module is the engine the backend embeds. Card data lives in `forge-gui/res`.
- `setup/` — Postgres dump + onboarding. `STEPS/` and `THEPLAN.md` are plans, not code. Root `BOOT-INF/` is a leftover exploded jar; ignore.
- `docker/` — compose deployment: `docker-compose.yml` (db + backend + web + one-shot `seed` container), `backend/Dockerfile`, `web/Dockerfile` + `nginx.conf`, `seeds/run-seeds.sh` + `seed_demo_accounts.sql`. Stack publishes **17170 (web)** and **17172 (backend)**.

## Backend
- **Maven is not on PATH on this machine.** Use the portable `C:\Users\student\AppData\Local\Temp\opencode\apache-maven-3.9.9\bin\mvn.cmd` (prepend to `$env:Path`), then run from `backend/` (no mvnw; target JDK 17, dev box runs 21).
- Build with `mvn clean package -DskipTests`. The running jar (`backend/target/campusforge-backend-0.0.1-SNAPSHOT.jar`) **file-locks itself** — stop java first (`restart-backend.ps1` kills *all* java processes) or the build can't overwrite it.
- **Forge engine must be built first:** `mvn -pl forge-headless -am install -DskipTests` from `forge-engine/`. The backend build resolves `forge:forge-headless:2.0.14-SNAPSHOT` from the local Maven repo. Without this, the backend won't compile.
- At startup `ForgeEngineBootstrap` calls `forge.headless.ForgeBootstrap.init()`, which resolves card data relative to the working dir (`forge-gui/res` → `../forge-gui/res` → `../forge-engine/forge-gui/res`). Run the jar from `backend/` (the scripts do), or set `-Dforge.res.dir`.
- Run/restart: `start-backend.cmd` (Windows), `restart-backend.ps1` (Windows), `restart-backend.sh` (Linux). Logs: `backend/backend.log(.err)`.
- Full rebuild + restart (kills java+deno, builds forge→backend→frontend, starts both, health-checks): `powershell -ExecutionPolicy Bypass -File restart-all.ps1` from repo root.
- Tests: `mvn test`; single suite with `-Dtest=LevelServiceTest`. Suites: deck, collection, qr, analytics, security, common, cohort, trade.
- Live Postgres concurrency proof: `mvn test -Dtest=TradeConcurrencyTest -Ddb.integration=true` (`@EnabledIfSystemProperty` — skipped in plain `mvn test`; needs the dev DB up). Creates throwaway cards/players and cleans up.
- Level/xp source of truth: `common/LevelService` (`level = 1 + xp/100`). `MatchManager.rewardWinner` and `CollectionService.discover` both recompute level through it — don't inline the formula elsewhere.
- Cohorts: players carry `degree_level`/`specialization` (migration V10). Source of truth `common/Cohort.java`: B.Tech specs CSE/CSAI/CSAM/CSB/CSSS/CSD/CSECON/ECE/EVE, M.Tech CSE/ECE, `isValid()`, `departmentOf()` (CSE dept = CSE/CSAI/CSAM/CSB/CSSS/CSD/CSECON, ECE dept = ECE/EVE). `RegisterRequest` requires both; `GET /api/v1/leaderboard` accepts `degreeLevel`/`specialization`/`department` filters. Test cohorts seeded by `setup/seed_cohorts.sql`.
- DB: PostgreSQL `campusforge` on localhost:5432, `postgres`/`postgres` (`src/main/resources/application.properties`). `ddl-auto=validate` + Flyway migrations V1–V14 (`src/main/resources/db/migration`). To reseed: restore `setup/campusforge_dump.sql` (includes test accounts and `RG Combat` decks); `setup/` also has `seed_claims.sql`, `seed_rg_combat_decks.sql`, `seed_cohorts.sql`, `seed_unique_cards.sql`, `seed_admin.sql`, `seed_events.sql` (idempotent; admin + event seeds run after backend has started once). Never hand-edit schema; add a migration. NOTE: since V14, `seed_claims.sql` must also insert `token_core` (NOT NULL).
- Auth: JWT Bearer token; endpoints under `/api/v1`. **Security semantics:** missing/invalid credentials → 401 (entry point); validly-authenticated user hitting a forbidden path → **403** (explicit `accessDeniedHandler`); `"/error"` is `permitAll()` so `sendError`-based responses (404 unknown paths, etc.) aren't rewritten to 401 by the `/error` dispatch re-entering the chain. Login/register responses are `Cache-Control: no-store`; CORS allows only `Authorization, Content-Type, Accept, X-Requested-With` headers. Rate limiting (`security/`, in-memory token buckets, no deps): `POST /auth/login|register` per-IP burst 30, `POST /claim` per-user+IP — `429` + `Retry-After` + JSON body. Secrets via env (`jwt.secret`, `jwt.expiration`, `campusforge.qr.signing-secret`) with dev defaults.
- QR claims: minted tokens are **signed** `V1.<CORE>.<SIG>` (HMAC-SHA256 via `qr/QrCodeSigner`, constant-time compare; CORE = 12 base32-ish chars). `ClaimService.claim` verifies the signature — forged/tampered → **400 before any DB lookup** — and legacy bare cores still resolve via `claims.token_core` (V14, unique index `uk_claims_token_core`). UNLIMITED claims reusable, UNIQUE one-shot (row lock).
- QR print catalog: `QrCatalogExporter` (`@ApplicationRunner`) auto-writes `qr-catalog/cards.json` + `cards.csv` on startup — every card gets a deterministic token core (`SHA-256("cf-print:" + cardId)` → 12 chars in `TOKEN_ALPHABET`), so re-runs produce identical codes and new cards are auto-added. Claims are created idempotently for cards that don't have one yet. Directory configurable via `campusforge.qr.catalog-dir` (default `qr-catalog`, resolved relative to CWD which is `backend/`). Admin endpoints: `GET /api/v1/admin/qr-catalog?format=json|csv` (live, no file I/O), `POST .../qr-catalog/regenerate` (re-exports files).
- Analytics: `analytics/` package. `GET /api/v1/analytics/decks?limit=` (popular decks) and `GET /api/v1/analytics/buildings?limit=` (active buildings from claims); limit clamped 1–100. `ProfileStatsDto.buildingsVisited` (distinct, sorted) on `GET /players/{id}/stats` (UNLOCK claims set `claimed_by`/`claimed_at`).
- Trading: `trade/` package (`TradeService`, `TradeController`). Trades are **multi-card bundles** of UNIQUE cards only (migration V11: `trades` + `trade_cards`). Accept is `@Transactional`: locks the trade row (`findByIdForUpdate` PESSIMISTIC_WRITE), locks all involved cards in **sorted-UUID order** (`UniqueCardRepository.findAllByIdForUpdate`) to avoid deadlock, re-verifies ownership, swaps owners, appends `"<ts>: <from> → <to> via trade <id>"` to `unique_cards.history`. 24h TTL; read paths lazily persist EXPIRED, accept/decline/cancel on expired → 410. Role rules: receiver accepts/declines, sender cancels. Related endpoints: `GET /collection/unique` (mine), `GET /players/search?q=`, `GET /players/{id}/unique-cards` (partner's uniques).
- Events: `events/` package. `events` table (V12) with `allowed_sets_json` + `bonus_multiplier`; active events gate matches via `DeckValidationService.validate(player, request, Event)` — non-basic `setCode ∉ allowed_sets` ⇒ `NOT_IN_EVENT`, UNLIMITED basics exempt. Bonus XP: discovery 10×mult, match win 50×mult (via `CollectionService.discover` / `MatchManager.rewardWinner`). Deleting an event cascades to its claims/matches (V13 `ON DELETE CASCADE`). Endpoints: `GET /api/v1/events`, `/events/active`, `/events/{id}`; admin CRUD under `/api/v1/admin/events`.
- Achievements + feed: `achievements/` (`AchievementCatalog` is the single source of truth; `player_achievements` table; `PlayerStatsService` sweeps before badges) and `feed/` (in-memory ring CAPACITY=50, STOMP `/topic/feed`, REST `GET /api/v1/feed` history; admin audit `GET /api/v1/admin/audit` is the same ring).
- Admin: `admin/` package (`AdminPlayerController`: `GET /api/v1/admin/players?q=`, `POST .../{id}/ban|unban`, `POST .../{id}/role` with `{ "role": "…" }`), `AdminClaimController` (`POST /api/v1/admin/claims` mint), `AdminEventController`, `AdminAuditController`. All under `/api/v1/admin/**` → `hasRole("ADMIN")`.

## Battle / WebSocket
- Matches run **in-process** (`MatchManager` → `ForgeMatchSession` around `forge.headless`), not as separate processes.
- STOMP endpoint `/ws/match` (raw WS and SockJS). Auth = `Authorization: Bearer <jwt>` header on the STOMP CONNECT frame (`StompAuthChannelInterceptor`).
- State topics: `/topic/match/{matchId}/p0` and `/topic/match/{matchId}/p1` (per seat). Submit choices to `/app/match/{matchId}/action` with `{ actionType: 'CHOICE', payload: { requestId, selectedIndices } }`.
- **Battle board layout:** Both players have vertical health bars (`HealthBar` component, color-coded green/yellow/red) and horizontal mana bars per color (`ManaBars` component). Opponent stats panel is above their battlefield; player stats panel is above "Your Battlefield". Phase strip, instruction banner, and action bar remain in their positions.
- **Action bar confirm row:** The Attack/Block/Confirm button only appears when ≥1 cards are selected (`selected.size > 0` in `ActionBar`). With 0 selected, only the hint text ("Tap cards to select them.") is shown for attack/block/choose types. For `play` type, "Pass Priority" appears independently via `showPass`.
- **Instant-speed spell filtering:** `battleUi.ts` exports `isInCombatPhase()` and `isInstantSpellLabel()`. `matchOptionsToCards(phase)` filters instant-speed spells (labels containing "— Instant") to `zone: 'none'` when the current phase is not a `COMBAT_*` phase, so Giant Growth/Shock/etc. are only tappable during combat. Outside combat, instant-speed text options are also hidden from the ActionBar, and the auto-skip effect fires (passing automatically) when the only remaining plays are mana abilities + filtered instants. This is frontend-only; the backend still generates all playable options.
- **Card art in battle:** Art always renders. In art mode (`showArt=true`) cards show full `aspect-ratio: 488/680` art. In text mode (`showArt=false`) cards get class `text-mode` → CSS crops art to 40px strip. Toggle persists to `localStorage` key `cf_card_display`.
- **Mana affordability:** `CostPartMana.canPay()` always returns `true` (engine TODO). `HumanPlayerController.getPlayableSAs()` uses `ComputerUtilMana.canPayManaCost()` to filter unaffordable spells. `forge-headless` depends on `forge-ai` so this is available.
- **Concede flow:** `MatchManager.reportConcede()` pushes a terminal `{ gameOver: true, status: "CONCEDED" }` state to both player STOMP topics *before* canceling the session, so the remaining player sees "You Lose" immediately.
- E2E driver: from `web-client/`, `node scripts/battle-e2e.cjs`. Prereqs: backend running; seeded DB with `testbattle@campus.edu` / `opponent@campus.edu` (pw `password123`), each owning a deck named `RG Combat`. Env: `BASE` (default is a LAN IP `http://192.168.194.106:17170`, not localhost), `WS_URL`, `STRATEGY` (`smash` default / `mirror`), `MAX_TURN`.
- Battle UI smoke: from `web-client/`, `node scripts/battle-ui-smoke.cjs`. Renders the **new** battle board (phase strip, instruction banner, opponent row, tap-to-act hand/battlefield cards, Pass Priority, attack confirm, concede) in headless Chrome against the Deno proxy: logs in as testbattle through the UI, creates a PvP lobby, joins with a scripted opponent whose seat is played by a page-injected STOMP bot, and clicks through the UI. Needs `dist/` rebuilt + `serve.mjs` running + both seeded accounts. **Deno must be running** (`deno run --allow-net --allow-read --allow-env serve.mjs` from `web-client/`) — the smoke test hits localhost:17170 which is the Deno proxy, not the Vite dev server.
- Offline e2e: from `web-client/`, `node scripts/offline-e2e.cjs`. Prereqs: `npm run build`; `dist/` served via Deno `serve.mjs` (use `PORT=17171` if 17170 is taken by the dev server); backend + seeded login account. - On a **fresh DB** the catalog order matters: `StarterCardSeeder` (`@Order(1)`) seeds 15 combat creatures first; `CardCatalogSeeder` inserts its 80 cards individually (`existsByOracleId`) so the full 95-card catalog + UNIQUE cards land regardless. - `seed` only runs on container creation — `docker compose rm -sf seed` (or `down -v`) before `up` to re-seed.

## Conventions
- Backend is the single source of truth for identity, collection/ownership, QR, trades, events, persistence. Forge only executes rules via `forge.headless` and must never touch PostgreSQL or know about the game economy.
- Dev environment is Windows/PowerShell; `.sh` scripts target Linux deploys.
